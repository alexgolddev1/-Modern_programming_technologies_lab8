# Детальний звіт з лабораторної роботи №8
## Тема: Розробка масштабованого CRUD Web API на базі .NET 8, ADO.NET та MS SQL Server у Docker-контейнерах

---

## 1. Мета та завдання дослідження
**Мета:** Вивчення принципів побудови архітектури RESTful Web API, опанування низькорівневої роботи з базами даних через технологію ADO.NET та автоматизація розгортання середовища через Docker Compose.

**Завдання:**
1. Секціонування проекту на логічні шари (Models, Repositories, Controllers).
2. Реалізація стійкого з'єднання з MSSQL Server всередині ізольованої мережі Docker.
3. Написання збережених процедур для мінімізації SQL-ін'єкцій та підвищення продуктивності.
4. Документування API за допомогою стандарту OpenAPI (Swagger).

---

## 2. Теоретична база та вибір технологій

### 2.1. ASP.NET Core Web API (NET 8)
Використано найновішу версію платформи .NET, що забезпечує високу швидкість обробки запитів та вбудовану підтримку Dependency Injection (DI). В проекті DI використовується для реєстрації репозиторію, що дозволяє легко замінювати логіку доступу до даних без зміни контролерів.

### 2.2. ADO.NET проти Entity Framework (ORM)
Хоча сучасні проекти часто використовують ORM (як Entity Framework), у даній роботі свідомо обрано **ADO.NET** (`Microsoft.Data.SqlClient`).
- **Переваги:** Повний контроль над SQL-запитами, відсутність оверхеду на мапінг об'єктів, вища швидкість виконання складних процедур.
- **Архітектурний підхід:** Використання `SqlDataAdapter` та `DataTable` для обробки результатів, що дозволяє гнучко працювати зі схемами даних.

### 2.3. Збережені процедури (Stored Procedures)
Вся бізнес-логіка бази даних винесена на сторону сервера MSSQL. Це забезпечує:
1. **Безпеку:** Код програми не містить SQL-запитів (SQL Injection safe).
2. **Продуктивність:** SQL Server компілює плани виконання процедур один раз і використовує їх повторно.
3. **Чистоту коду:** Репозиторій C# лише викликає назву процедури та передає параметри.

## 3. Детальний опис архітектури рішення

### 3.1. Шар моделей (`ProductApp/Models/EmployeeModel.cs`)
Модель виконує роль DTO (Data Transfer Object) та містить логіку валідації.
- Атрибут `[Required]` гарантує, що база даних не отримає `NULL` у критичних полях.
- Атрибут `[Display]` покращує візуалізацію даних у Swagger.

### 3.2. Шар доступу до даних (`ProductApp/Repository/EmployeeRepository.cs`)
Це серце проекту. Реалізація включає:
- **Управління ресурсами:** Використання блоків `using` гарантує закриття SQL-з'єднань навіть у разі помилок, запобігаючи витоку пам'яті.
- **Мапінг даних:** Ручний перенос даних з `DataRow` у об'єкти C# забезпечує повну прозорість процесу.
- **Зворотний зв'язок:** Методи повертають `bool`, що дозволяє контролеру коректно формувати HTTP-статуси (200 OK або 400 Bad Request).

### 3.3. Шар контролерів (`ProductApp/Controllers/EmployeeController.cs`)
Контролер не знає про базу даних. Він взаємодіє лише з репозиторієм.
- **Маршрутизація:** Використано атрибутний мапінг `[Route("api/[controller]")]`.
- **Swagger:** Завдяки анотаціям, API автоматично генерує документацію, доступну за адресою `/swagger`.

## 4. Контейнеризація та автоматизація (DevOps частина)

Проект використовує складну схему з трьох сервісів для забезпечення принципу "запуск однією кнопкою":

1.  **Сервіс `db` (Database):**
    Використовує офіційний образ `mcr.microsoft.com/mssql/server:2022-latest`. Налаштований на використання складного пароля для відповідності політиці безпеки MSSQL.
2.  **Сервіс `api` (Application):**
    Використовує Dockerfile з багатоетапною збіркою (`multi-stage build`). Це дозволяє отримати фінальний образ мінімального розміру (тільки Runtime, без вихідного коду).
3.  **Сервіс `db-init` (Миграції):**
    Спеціальний контейнер-помічник. Він чекає на запуск сервера бази даних і за допомогою утиліти `sqlcmd` виконує скрипт `init.sql`. Це вирішує проблему "курки та яйця", коли API намагається підключитися до бази, яка ще не встигла завантажитись.

## 5. Тестування та обробка помилок

### 5.1. Типові сценарії перевірки:
- **Сценарій "Успіх":** POST запит з валідним JSON повертає статус 200 та повідомлення про успіх.
- **Сценарій "Помилка методу":** Спроба виконати GET на POST-ендпоїнт повертає **405 Method Not Allowed** (важливо для безпеки).
- **Сценарій "Порожні дані":** Валідація моделей повертає 400 Bad Request з переліком полів, які потрібно заповнити.

## 6. Розширені відповіді на контрольні запитання

1.  **Що таке ADO.NET і для чого він використовується?**
    Це фундаментальна бібліотека класів .NET для роботи з даними. Вона використовується як "нижній рівень" для всіх інших бібліотек (включаючи Entity Framework). Її обирають, коли потрібна максимальна продуктивність, прямий контроль над транзакціями та специфічні фічі конкретної БД.
2.  **Які є основні об'єкти в ADO.NET і як вони пов'язані?**
    - `SqlConnection`: Створює фізичний канал зв'язку з БД.
    - `SqlCommand`: Об'єкт, що містить SQL-текст або назву процедури.
    - `SqlParameter`: Забезпечує безпечну передачу даних у команду.
    - `SqlDataAdapter`: Виконує роль "насоса", який викачує дані з команди у локальний буфер (`DataTable`).
3.  **Як підготувати та виконати SQL-запит до бази даних за допомогою ADO.NET?**
    Процес складається з: 
    1) Створення рядка підключення (`ConnectionString`).
    2) Ініціалізації `SqlConnection` у блоці `using`.
    3) Налаштування `SqlCommand` (встановлення `CommandType = StoredProcedure`).
    4) Додавання параметрів через колекцію `Parameters`.
    5) Виклику `ExecuteNonQuery` (для змін) або `ExecuteReader/Fill` (для читання).

## 8. Контрольні запитання та відповіді

### 1. Що таке ADO.NET і для чого він використовується в розробці програмного забезпечення?
**Відповідь:** ADO.NET (ActiveX Data Objects for .NET) — це набір бібліотек, що входять до складу Microsoft .NET Framework, які забезпечують взаємодію між програмним кодом та різними джерелами даних.
- **Призначення:** Він використовується для створення надійних, масштабованих додатків, які потребують прямого доступу до даних. ADO.NET дозволяє підключатися до БД, виконувати команди (SELECT, INSERT, UPDATE, DELETE) та обробляти результати.
- **Ключова особливість:** Модель "від'єднаних даних" (disconnected data), де дані можна завантажити в пам'ять (DataSet/DataTable), розірвати з'єднання, обробити їх і пізніше синхронізувати зміни з базою.

### 2. Які є основні об'єкти в ADO.NET і як вони пов'язані між собою?
**Відповідь:** Архітектура ADO.NET базується на двох основних компонентах: **Data Provider** (для роботи з конкретною БД) та **DataSet** (універсальне сховище в пам'яті).
- **SqlConnection:** Створює фізичний канал зв'язку між додатком та сервером БД. Без нього жодна операція неможлива.
- **SqlCommand:** Об'єкт, що містить інструкцію (SQL-текст або назву процедури), яку треба виконати через відкрите з'єднання.
- **SqlDataReader:** Забезпечує швидкий, односпрямований доступ до результатів запиту в режимі "тільки читання". Працює лише при відкритому з'єднанні.
- **SqlDataAdapter:** Виконує роль посередника (моста). Він використовує `SqlCommand` для наповнення `DataSet` або `DataTable` даними з бази та навпаки — передає зміни з пам'яті в базу.
- **DataTable/DataSet:** Об'єкти в оперативній пам'яті, що зберігають копії таблиць БД, дозволяючи працювати з ними без активного з'єднання.

### 3. Як підготувати та виконати SQL-запит до бази даних за допомогою ADO.NET?
**Відповідь:** Процес виконання запиту зазвичай складається з наступних кроків:
1. **Визначення Connection String:** Рядок, що містить адресу сервера, назву бази та дані для авторизації.
2. **Ініціалізація об'єктів:** Створення екземплярів `SqlConnection` та `SqlCommand`.
3. **Налаштування команди:** 
   - Встановлення властивості `CommandType` (`Text` для SQL-запиту або `StoredProcedure` для процедури).
   - Прив'язка до з'єднання через `Command.Connection`.
4. **Параметризація:** Використання об'єктів `SqlParameter` (наприклад, `cmd.Parameters.AddWithValue(...)`) для безпечної передачі даних, що запобігає SQL-ін'єкціям.
5. **Відкриття з'єднання:** Виклик `connection.Open()`.
6. **Виконання:**
   - `ExecuteNonQuery()` — для команд, що не повертають таблицю (Insert/Update/Delete).
   - `ExecuteReader()` — для отримання набору рядків.
   - `ExecuteScalar()` — для отримання одного значення (наприклад, суми або ID).
7. **Закриття:** Обов'язкове закриття з'єднання (найкраще використовувати блок `using`).
